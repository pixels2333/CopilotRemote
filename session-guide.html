当前实现

Bridge 在 main.ts 中启动，硬编码连接到 127.0.0.1:9229 上的 VS Code CDP，镜像其中的 Copilot Chat 会话。

Flutter 客户端通过 WebSocket 连接到 Bridge：

chatProvider.notifier.connect('ws://127.0.0.1:17321/copilot-mirror/ws')

所有 Flutter 客户端收到的是 同一个会话 的数据。

如何实现

每个 VS Code 窗口有自己的 CDP 端口（通过 --remote-debugging-port 指定）。每个 Bridge 实例连接一个 VS Code，用不同 WebSocket 端口避免冲突：

# 终端 1 — 项目 A
npx tsx src/main.ts --cdp-port 9229 --ws-port 17321

# 终端 2 — 项目 B  
npx tsx src/main.ts --cdp-port 9230 --ws-port 17322

# 终端 3 — 项目 C
npx tsx src/main.ts --cdp-port 9231 --ws-port 17323

Flutter 端通过切换连接地址来切换"会话"（实际是切换 VS Code 窗口）：

// 连接项目 A
chatProvider.notifier.connect('ws://192.168.1.10:17321/copilot-mirror/ws')

// 连接项目 B
chatProvider.notifier.connect('ws://192.168.1.10:17322/copilot-mirror/ws')

// 连接项目 C
chatProvider.notifier.connect('ws://192.168.1.10:17323/copilot-mirror/ws')

注意 --cdp-port 和 --ws-port 是 CLI 参数，目前 main.ts 从 DEFAULT_BRIDGE_OPTIONS 读取，需要扩展支持环境变量或命令行解析。

现状

Bridge 目前只关注 一个 Copilot Chat 选项卡（通过 DOM 选择器定位当前可见的聊天面板）。VS Code 的 Copilot 在同一个 auxiliarybar 中仅有一个活跃的聊天视图，切换话题会替换当前内容。

如果要支持同窗口多标签

需要 Bridge 端扩展能力：

  • 通过 CDP 的 Runtime.evaluate 调用 VS Code API 枚举所有聊天会话
  • 暴露 session.list 和 session.switch 命令
  • Flutter 端发送 client.command.switchSession 切换 Bridge 监听的 DOM 目标
// 协议扩展（提议）
type: 'session.list'
→ 返回: [{ sessionId, title, lastActive }, ...]

type: 'client.command.switchSession'
payload: { sessionId: 'vscode-window-1/copilot-chat/2' }
→ Bridge 切换 DOM 监听目标

目前尚未实现 — 需要 VS Code Copilot Chat 的 API 支持来枚举和切换会话。

📱 Flutter 端切换连接的完整流程

现有的连接入口

在 chat_provider.dart 中：

// ChatNotifier.connect()
Future connect(String url, {String? authToken}) async {
  state = state.copyWith(connectionStatus: ConnectionStatus.connecting);
  _wsService?.dispose();
  _wsService = WebSocketService(url: url, authToken: authToken);
  // ...
  await _wsService!.connect();
}

操作方式

  1. 启动 Node.js Bridge
    在对应项目目录下运行 npm run build 后执行 node dist/main.js，Bridge 自动连接 VS Code CDP
  2. Flutter 连接 Bridge
    chatProvider.notifier.connect('ws://192.168.1.10:17321/copilot-mirror/ws')
    连接成功后收到 server.hello，显示 ✅ Connected
  3. 切换会话
    调用 chatProvider.notifier.disconnect() 断开当前，再 .connect(newUrl) 连到另一个 Bridge
  4. 在聊天的过程中切换
    同样先 disconnect() → connect(newUrl)，旧的聊天记录会被 session.snapshot 刷新

建议的 UI 交互（待实现）

在 Flutter 中可增加：

  • 设置页面：输入框修改 Bridge URL + 保存到本地存储
  • 连接扫码：Bridge 启动时打印二维码（含 URL + token），Flutter 扫码自动填入
  • 会话列表：如果 Bridge 实现了 session.list，在下拉列表中选择
  • 多连接：同时维持多个 Bridge 连接，TabBar 切换不同 VS Code 窗口

实际使用示例

// 1. 在家连工作电脑
chatProvider.notifier.connect(
  'ws://192.168.1.10:17321/copilot-mirror/ws',
  authToken: 'my-secret-token',
);

// 2. 切换到工作电脑的另一个项目（另一个 Bridge 实例）
chatProvider.notifier.disconnect();
chatProvider.notifier.connect(
  'ws://192.168.1.10:17322/copilot-mirror/ws',
  authToken: 'my-secret-token',
);

// 3. 出门切换到手机热点上的笔记本
chatProvider.notifier.disconnect();
chatProvider.notifier.connect(
  'ws://192.168.1.20:17321/copilot-mirror/ws',
  authToken: 'my-secret-token',
);
总结：当前版本是 1 Bridge ↔ 1 VS Code 模式。
切换"会话" = 切换 Flutter 连接的 WebSocket URL（指向不同的 Bridge 实例）。
同窗口多标签切换需要额外协议扩展。
